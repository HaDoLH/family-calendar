# 準時鬧鐘設定步驟（Cloudflare Worker）

約 15 分鐘，一次設定之後不用再管。

## 為什麼要做這個

GitHub Actions 的排程**極不可靠**：

- 實測延遲 6～12 小時（說好台北 09:00，下午 15:27～16:39 才跑）
- 而且會大量丟棄：設定每 30 分鐘，14 小時只執行 2 次，間隔曾達 8.7 小時

提醒類功能不能建立在這種基礎上。

但 GitHub 的**手動觸發**（workflow_dispatch）是即時的，不排隊。所以讓 Cloudflare 當準時的鬧鐘，時間到就去按那顆按鈕。

**推播邏輯完全不動**，還是跑 `scripts/notify.js`，只是換一個準時的人去按。

---

## 步驟一：拿一把 GitHub 鑰匙

1. GitHub 右上頭像 → **Settings**
2. 左側最下面 **Developer settings**
3. **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
4. 填寫：
   - **Token name**：`family-calendar-cron`
   - **Expiration**：選最長的（⚠️ 見下方注意事項）
   - **Repository access**：選 **Only select repositories** → 只勾 `family-calendar`
   - **Permissions** → **Repository permissions** → 找到 **Actions** → 改成 **Read and write**
5. 按 **Generate token**，把那串 `github_pat_...` **複製起來**（只會顯示一次）

> 這把鑰匙只能動 `family-calendar` 這一個 repo 的 Actions，權限已經壓到最小。

---

## 步驟二：建立 Cloudflare Worker

1. 到 `dash.cloudflare.com` 註冊（免費，用 email 即可）
2. 左側 **Compute (Workers)** → **Create** → **Start with Hello World!** → **Deploy**
3. 部署完按 **Edit code**，把編輯器裡的內容全選刪掉，貼上本資料夾的 `worker.js`
4. 右上 **Deploy**

## 步驟三：把鑰匙交給它

1. 回到這個 Worker 的頁面 → **Settings** → **Variables and Secrets**
2. **Add** → 型態選 **Secret**
   - **Variable name**：`GITHUB_TOKEN`（⚠️ 名字要一模一樣）
   - **Value**：貼上步驟一那串 token
3. **Deploy**

## 步驟四：設定鬧鐘時間

1. **Settings** → **Trigger Events** → **Cron Triggers** → **Add**
2. 加入兩組（Cloudflare 用 UTC，台北時間要減 8 小時）：

| Cron | 台北時間 | 推什麼 |
|---|---|---|
| `0 1 * * *` | 09:00 | 今天的行程 |
| `0 13 * * *` | 21:00 | 明天的行程 |

---

## 步驟五：立刻測一次

打開 Worker 的網址（長得像 `xxx.workers.dev`），應該回覆「已嘗試觸發」。

然後到 GitHub repo → **Actions** → 看「每日行程推播」有沒有在幾秒內出現一次新的執行紀錄。有就成功了。

網址後面加 `?mode=tomorrow` 可以測另一組。

---

## ⚠️ 注意事項

**Token 會過期。** 到期後鬧鐘會安靜地停掉，不會有任何錯誤通知 —— 跟先前「推播訂閱失效」是同一類陷阱。設定時把到期日記在行事曆上（可以直接在行程表裡排一筆提醒）。

**GitHub 原本的排程不要刪。** 它雖然不準，但留著當備援：萬一 Cloudflare 那邊出問題，稀疏的執行加上放寬的時段還是有機會送出。而且「今天這則送過了沒」記在資料庫裡，兩邊同時觸發也不會重複推播。
